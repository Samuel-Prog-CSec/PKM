> [!info]+ Enunciado (resumen)
> El hospital **"Cuidamos Tu Salud"** construye una app para controlar pacientes vacunados de COVID-19 (dos tipos: los que han pasado la COVID y los que no). Requisitos:
> - **Datos genéricos del paciente**: nombre, apellidos, DNI, año de nacimiento, dirección, localidad, provincia, teléfono y nº de historial clínico.
> - **Datos de las vacunas**: primera dosis (al ponerla se comprueba si ha pasado la COVID y se refleja en el paciente); segunda dosis a los 2 meses (solo si no la pasó); dosis de recuerdo a los 3 meses (todos). De cada vacuna: nombre, lote y fecha.
> - Permitir **eliminar pacientes**.
> - Generar un **listado** de pacientes con derecho a **pasaporte COVID** (dos dosis, o una dosis y haber pasado la COVID).
> - Generar un **informe con el porcentaje** de pacientes que han recibido alguna dosis.
> - *Otros datos del paciente (baja por COVID, alta por recuperación) los mantiene **otra aplicación**.*
> - **Menú**: alta paciente · registrar vacuna · registrar paciente que ha pasado la COVID · eliminar paciente · informe pasaporte COVID · informe % vacunados.
>
> **Pide: Puntos de Función sin ajustar (PFSA).**

> [!tip]+ El menú es tu mapa de transacciones
> Cuando el enunciado da un **menú**, casi cada opción es un **proceso elemental** (una transacción). Es la mejor pista para no dejarte ninguna.

## Paso 1 · Frontera

La aplicación medida es la del hospital. Existe **otra aplicación** que mantiene la "baja por COVID" y el "alta por recuperación".

> [!warning]+ Distractor
> <mark style="background: #FF5582A6;">Esos datos los mantiene otra app **y la nuestra no los lee** → no se cuentan</mark> (ni ILF ni ELF). Solo sería ELF un fichero externo que **referenciáramos**, y aquí no se referencia.

## Paso 2 · Funciones de datos

Siguiendo el criterio de clase (entidades distintas = **ILF separados**, como `Pedido`/`Detalle_Pedido` en el caso PCGeek), las **vacunas** son una entidad propia, no un subgrupo del paciente:

- **ILF Paciente** — DET: nombre, apellidos, DNI, año nacimiento, dirección, localidad, provincia, teléfono, nº historial e indicador "ha pasado la COVID" (**10**). 1 RET → **Baja → 7**.
- **ILF Vacuna** — DET: nombre de vacuna, lote, fecha (+ paciente) (**3-4**). 1 RET → **Baja → 7**.

No hay **ELF** (el dato externo es el distractor).

| Función de datos | Tipo | DET | RET | Complejidad | PF |
| - | - | - | - | - | - |
| Paciente | ILF | 10 | 1 | Baja | **7** |
| Vacuna | ILF | 3-4 | 1 | Baja | **7** |

## Paso 3 · Funciones transaccionales

Las cuatro primeras opciones del menú **mantienen** datos → **EI**; los dos informes **derivan** datos → **EO**. **Registrar vacuna** mantiene Vacuna y además **lee Paciente** (comprueba si pasó la COVID en la 1.ª dosis) → 2 FTR → **Media**. Los informes referencian Paciente + Vacuna → 2 FTR.

| # | Transacción | Tipo | DET | FTR | Compl. | PF |
| - | - | - | - | - | - | - |
| 1 | Alta paciente | EI | 9 + botón + msg = 11 | 1 | Baja | 3 |
| 2 | **Registrar vacuna** | EI | nombre, lote, fecha + id + botón + msg = 6 | **2** (Vacuna + Paciente) | **Media** | **4** |
| 3 | Registrar "ha pasado la COVID" | EI | id + indicador + botón + msg = 4 | 1 | Baja | 3 |
| 4 | Eliminar paciente | EI | id + botón + msg = 3 | 1 | Baja | 3 |
| 5 | Informe pasaporte COVID | **EO** | campos paciente + elegibilidad ≈ 6-19 | **2** (Paciente + Vacuna) | **Media** | **5** |
| 6 | Informe % de vacunados | **EO** | % + total ≈ 2 | **2** (Paciente + Vacuna) | Baja | **4** |

<mark style="background: #FFB86CA6;">El informe del pasaporte es **EO**</mark>: para la elegibilidad hay que **contar dosis** y combinarlas con el indicador de COVID (dato derivado). El del porcentaje también es EO (cálculo). No hay consulta pura → **0 EQ**.

## Paso 4 · Total

| Tipo | Baja | Media | Alta | PF |
| - | - | - | - | - |
| ILF | 2×7 | | | 14 |
| ELF | | | | 0 |
| EI | 3×3 | 1×4 | | 13 |
| EO | 1×4 | 1×5 | | 9 |
| EQ | | | | 0 |
| | | | **PFSA** | **36** |

> [!success]+ Resultado
> <mark style="background: #8000E1A6;">**PFSA = 36 Puntos de Función sin ajustar.**</mark>

> [!note]+ Decisiones de criterio
> - **Vacuna como ILF separado** (entidad propia), siguiendo el criterio de clase. Si se modelara como **RET** del paciente, saldría ≈ **27 PFSA** (un solo ILF y menos FTR). El propio enunciado de clase avisa de que el resultado varía según la interpretación; lo evaluable es justificarlo.
> - El dato "baja por COVID / alta por recuperación" **no se cuenta**: lo mantiene otra app y no lo referenciamos (distractor clásico).
> - "Registrar que ha pasado la COVID" es una **EI propia** (modifica el indicador del paciente), distinta del registro de vacunas.
> - *Matiz*: si "eliminar paciente" borrara en cascada sus vacunas, referenciaría 2 ficheros → Media (4) y el total subiría a 37.
