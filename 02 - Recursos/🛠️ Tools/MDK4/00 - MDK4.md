<mark style="background: #ADCCFFA6;">`mdk4` es un generador de tramas 802.11 organizado en módulos de ataque</mark>: inundación de beacons, denegación de servicio por autenticación, fuerza bruta de SSID, confusión de WIDS, fuzzing. Cubre el hueco entre `aireplay-ng` —centrado en deauth y WEP— y escribir tramas a mano con Scapy.

Se mantiene bajo el paraguas de aircrack-ng en [aircrack-ng/mdk4](https://github.com/aircrack-ng/mdk4) y viene empaquetado en Kali.

> [!warning]+ `mdk3` está muerto: usar `mdk4`
> Buena parte del material de referencia —incluidos módulos de HTB— sigue enseñando `mdk3`, que **lleva años sin mantenimiento** y ya no está en los repositorios de las distribuciones actuales. <mark style="background: #FF5582A6;">`mdk4` es el sucesor</mark>, con la misma estructura de módulos y sintaxis casi idéntica. Cualquier comando `mdk3` de un tutorial antiguo se traduce cambiando el nombre del binario, revisando las banderas.

# Sintaxis

```shell-session
$ sudo mdk4 <interfaz> <módulo> [opciones]
```

La interfaz debe estar en modo monitor y con la inyección verificada — ver [[05 - Modos de operación y modo monitor]].

# Los módulos

| Módulo | Nombre | Qué hace |
| ------ | ------ | -------- |
| `b` | Beacon Flood | Inunda con beacons de SSID falsos |
| `a` | Authentication DoS | Autentica clientes falsos hasta agotar el AP |
| `p` | Basic probing / SSID Bruteforce | Sondea y descubre **SSID ocultos** |
| `d` | Deauthentication / Disassociation | Desconexión masiva o dirigida |
| `m` | Michael Countermeasures | DoS contra redes **TKIP** |
| `e` | EAPOL Start / Logoff | Inundación de la máquina de autenticación |
| `s` | 802.11s mesh | Ataques a redes malladas |
| `w` | WIDS Confusion | Confunde a los sistemas de detección |
| `f` | Packet Fuzzer | Tramas malformadas para provocar fallos |

## `p` — descubrir SSID ocultos

El uso más limpio y el que sustituye directamente a `mdk3 p`:

```shell-session
$ sudo mdk4 wlan0mon p -t D2:A3:32:13:29:D5 -f /opt/wordlist.txt
$ sudo mdk4 wlan0mon p -t A2:FF:31:2C:B1:C4 -b u -c 1
```

| Opción de `-b` | Espacio |
| -------------- | ------- |
| `u` | Mayúsculas |
| `l` | Minúsculas |
| `n` | Dígitos |
| `c` | Mayúsculas y minúsculas |
| `m` | Alfanumérico |
| `a` | Todos los imprimibles |

Ver [[07 - Descubrimiento de SSID ocultos]].

## `a` — denegación por autenticación

```shell-session
$ sudo mdk4 wlan0mon a -a 60:38:E0:XX:XX:XX     # contra un AP concreto
$ sudo mdk4 wlan0mon a -i 60:38:E0:XX:XX:XX     # intelligent test
```

Autentica clientes desde MAC aleatorias a más de mil por segundo hasta llenar la tabla de asociación. En equipamiento antiguo provoca el reinicio del AP, lo que sirve para **desbloquear WPS** — [[10 - DoS contra WPS con MDK4]]. `-i` mantiene vivos los clientes falsos reinyectando tráfico, aumentando la presión.

## `e` — inundación EAPOL

```shell-session
$ sudo mdk4 wlan0mon e -t 60:38:E0:XX:XX:XX        # EAPOL-Start
$ sudo mdk4 wlan0mon e -t 60:38:E0:XX:XX:XX -l     # EAPOL-Logoff
```

<mark style="background: #8000E1A6;">`EAPOL-Logoff` expulsa clientes **sin usar tramas de desautenticación**</mark>, lo que lo convierte en una alternativa cuando `PMF` bloquea el ataque clásico. `EAPOL-Start` satura la máquina de estados de autenticación.

## `d` — desautenticación

```shell-session
$ sudo mdk4 wlan0mon d -B 60:38:E0:XX:XX:XX -c 1
$ sudo mdk4 wlan0mon d -w whitelist.txt -c 1
```

Equivalente a `aireplay-ng -0` pero con listas blancas y negras de BSSID, lo que permite atacar todo un espectro salvo unos objetivos concretos. Sujeto a la misma limitación: **no funciona con `PMF` activo** — ver [[01 - Tramas de gestión y su valor ofensivo]].

## `b` — inundación de beacons

```shell-session
$ sudo mdk4 wlan0mon b -f ssids.txt -c 1 -s 100
```

Genera redes falsas. Su utilidad real no es el DoS sino **saturar el inventario de un WIDS** con cientos de BSSID inexistentes, dificultando la correlación de eventos reales.

## `w` — confusión de WIDS

```shell-session
$ sudo mdk4 wlan0mon w -e HTB-Wireless -c 1
```

Genera tráfico que hace que el WIDS marque como rogue APs a puntos legítimos, o que reporte roaming inexistente. <mark style="background: #FFB86CA6;">Es ruido dirigido contra la detección, no contra la red</mark>.

## `m` — contramedidas Michael (TKIP)

```shell-session
$ sudo mdk4 wlan0mon m -t 60:38:E0:XX:XX:XX
```

Explota que el estándar obliga al AP a cortar el servicio durante 60 segundos si recibe dos fallos de `MIC` Michael en menos de un minuto. Sólo aplica a redes **TKIP**, que hoy son un hallazgo en sí mismas — [[03 - Métodos de autenticación y cifrado]].

# Consideraciones operativas

> [!warning]+ Casi todo aquí es denegación de servicio
> Siete de los nueve módulos degradan o interrumpen el servicio de la red objetivo. <mark style="background: #FF5582A6;">Necesitan estar explícitamente en el alcance</mark>, y aun así conviene ejecutarlos fuera de horario y con el contacto técnico avisado. El único módulo inocuo en la práctica es `p` en modo diccionario.
>
> Y ninguno es sutil: miles de tramas por segundo desde MAC aleatorias es la firma que dispara cualquier WIDS. Ver [[09 - Detección y evasión]].

**Verificar la inyección antes**, o se pierde el tiempo:

```shell-session
$ sudo aireplay-ng --test wlan0mon
```

**Fijar el canal**, porque mdk4 no lo hace por sí solo en todos los módulos:

```shell-session
$ sudo iw dev wlan0mon set channel 1
```

# Alternativas

| Necesidad | Alternativa |
| --------- | ----------- |
| Deauth simple | `aireplay-ng -0` |
| Control total de la trama | **Scapy** — permite fijar `reason code`, secuencia y ritmo. Ver [[🔨📦 Scapy|Scapy]] |
| Evil twin | `hostapd-mana`, `eaphammer` |
| Todo integrado en menú | `airgeddon` |

Cuando el objetivo es **evadir detección** y no ir rápido, Scapy gana: mdk4 tiene firmas de temporización y de contenido bien conocidas, mientras que una trama construida a mano puede imitar el comportamiento de un cliente legítimo.
